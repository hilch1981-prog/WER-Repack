## 일반 이용

- 길드 가입 캐릭터: 일반 비행 조련사 → **길드하우스 이용** → **길드하우스로 이동**.
- 길드가 아직 하우스를 구매하지 않았다면 길드장에게만 구매 메뉴 제공. 공식 기본가격1000골드, 자동 무료 지급 아님.
- 길드 미가입자에게 메뉴를 표시하지 않으며 선택 시에도 소속을 재검사한다. 가입만으로 다른 길드의 집을 이용할 수 없다.
- 전투/사망/비행/전장/이동/운송수단 탑승 중에는 이동 거부. 기존 비행 경로·즉시비행 토글 유지.
- 별도 스크립트를 가진 퀘스트용 비행 NPC는 기본 스크립트 보존을 위해 메뉴 확장 대상에서 제외. 대체 명령 `.gh teleport`(일반유저 사용 가능).
- 관리 NPC 번호는900030(판매/이동),900031(집사),900032(여관주인). **원본 README의 .npc add 500030을 이 서버에서 사용하지 않는다.** 기존500030~32 상인은 보존한다. 별도의 판매 NPC를 도시에 자동 스폰하지 않고 비행 NPC 메뉴에서 구매/이동한다.

## 업데이트 시 보존 절차

1. 공식 기본브랜치/HEAD/날짜를 새로 조회. source_manifest.json의 기준SHA 및 upstream_delta.patch와 실소스 대조한다. upstream에 같은 수정이 들어왔다면 중복 적용하지 않는다.
2. 기존 module_staging은 원본 근거. 작업 사본에서 변경하고, 실행 중 빌드 입력을 수정하지 않는다. 공식 data/sql/db-world의 DELETE/REPLACE를 운영DB에 실행하지 않는다.
3. NPC900030~32 ↔ guildhouse.h GetCreatureEntry ↔ guild_house_spawns 여관주인 ↔ 모델/koKR 로케일을 함께 보존한다. 새 ID점유 발견 시 중단하고 재배치 결정. 포털500000~9는 실제 템플릿/로케일 확인 후 재사용.
4. 기존 private DB는 이미 guild_house/guild_house_spawns/mod_guildhouse_locale를 보유하므로 prepare_db.py는 전체 설치기가 아니라 **확인된 DB용 차이 이행기**다. 새DB에는 별도 충돌/스키마 검증 뒤 필요한 기본 데이터를 준비해야 한다. 기존 SQL을 통째 덮어쓰지 않는다.
5. DB before/result/SQL을 보존하고 롤백 시험 후 적용. source_manifest의6파일 해시·기존conf13개 값 동일성·MSVC /Zs·전체링크를 검증한다.
6. source_manifest/delta는 현재 준비본의 검증 가능한 재적용 자료다. 과거 원장의 해시를 지우지 않는다. 구문 검사를 전체 링크/게임 검증으로 쓰지 않는다.

## 게임 검증 대기 목록

- 길드 없음 / 하우스 없는 일반회원 / 길드장 구매 / 소유 길드원 이동.
- 메뉴 열기 후 탈퇴·등급 변경·다른 길드 가입 시 재검사.
- 잔액 부족, 중복 구매, 판매·재구매, 집사/시설 생성, 이미 보유한 시설 반복 요청.
- 서로 다른 길드의 같은 섬 격리, 펫/소환수 위상, 탈퇴·해산·재접속·차원문 귀환.
- 비행 조련사의 기존 퀘스트·택시 경로·즉시비행 토글, 특수 비행 NPC 예외.
- 기존 상인500030~32의 모델·상점·스폰 유지.

게임 검증은 사용자의 실제 클라이언트 테스트가 필요하다. 자동 후처리는 빌드입력/EXE해시·기동포트까지만 확인한다.
